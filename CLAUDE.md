# Warband Keeper : consignes de développement

Addon World of Warcraft (client WoW Forever, `## Interface: 16001`, API moderne : `C_Item`, `C_Container`, `TooltipDataProcessor`…). Toute l'interface et les textes sont en français.

## Notes de patch (obligatoire à chaque modification)

Chaque ajout, modification ou correction doit être noté **dans le même commit** :

1. Dans `Core/Changelog.lua` :
   - nouvelle version : ajouter une entrée **en tête** de `WK.Changelog` (version, date `JJ/MM/AAAA`, listes `added`, `changed`, `fixed`) ;
   - changement non publié : compléter l'entrée de tête.
   - `restart = true` dans l'entrée quand il faut redémarrer complètement le jeu (nouveau `.lua`, nouvelle texture, `.toc` modifié) ; sinon rien (un /reload suffit). Affiché en jeu (pastille), dans `CHANGELOG.md` et dans les Releases (le workflow corrige la mention s'il voit de nouveaux fichiers) ; le client le recalcule à l'installation.
   - Phrases courtes, en français, du point de vue du joueur (ce qui change pour lui, pas le détail du code). Une correction dit ce qui n'allait pas.
2. Déplacer de `WK.Roadmap` ce qui vient d'être livré ; y ajouter les idées acceptées mais pas encore commencées.
3. Monter la version dans `WarbandKeeper.toc` (`## Version`) **et** `Core/Init.lua` (`WK.version`) ; elles doivent être identiques à la version de tête du changelog.
4. Régénérer `CHANGELOG.md` : `python3 tools/gen_changelog.py`.

## Textures

Les textures de `Media/` sont générées par `python3 tools/gen_media.py` (Pillow). Un nouveau fichier de texture ou un nouveau `.lua` demande de **redémarrer le jeu** (un `/reload` ne suffit pas) : le signaler dans la note de version.

## Thèmes

Les couleurs viennent de `UI/Themes.lua` (un seul thème proposé : Graphite, imposé par `UI:ApplyTheme` ; les autres restent dans `UI.themes` sans choix dans les Options) : un thème donne quelques couleurs de base (`bg`, `line`, `frame`, `glow`, `text`, `muted`, `accent`) et `palette()` dérive le reste. Couleurs de sens communes à tous les thèmes : `positive`, `negative`, `warning`, `gold`, `tank`, `heal`, `dps`, `rare`, `info` (bleu : repos), `rule` (turquoise : automatique, par règle), `plan` (violet : mode plan), `silver` (secondaire, autre perso), `mint` (pastille de compte) ; dans un texte, `UI:Hex(C.x)`. Réglages d'Apparence (`settings.ui`, onglets Styles / Couleurs / Texte / Fenêtre ; dégradé, teinte, accent par perso, halo, police des titres, contraste, arrondi, style des cartes, fond et animation ne sont plus réglables à la main : seuls les styles posent `accent2`, `titleFont`, `rounding`, `bgTexture` ; les autres remis d'origine une fois, `lookTrim`) : `accent` (« theme », « class », n° de `UI.accents` ou « custom » = `accentRGB`), `bgTint` (cold / warm, décalage `TINTS` dans `ApplyTheme`), `font` (`UI.fonts`), `textScale` (`UI.textScale`, appliqué par `UI:Text`, qui ne descend jamais sous `UI.MIN_TEXT` = 10), `rounding`, `cardStyle` (flat / line / halo, `UI.cardStyle`, lu par `UI:Card`), `opacity`, `scale`, plus `accentPerChar` / `charAccent[perso]` (`UI:AccentChoice()`), `accent2` (`UI:Accent2()`, dégradé des jauges `UI:Progress`), `titleFont` (`UI.CARD_TITLE_FONT`, titres de `UI:Card`), `contrast` (soft / strong, `muted` décalé), `bgTexture` (grain / stone / parchment, `BG_TEX` de `UI/MainFrame.lua`), `glow` (0 à 2), `anim` (« none » coupe le fondu d'ouverture), `sideRight` (`UI:ApplySide`), `tipOpacity` (fond des infobulles habillées). Carte Apparence d'Options en onglets (`LOOK_TABS`, `cfg.lookTab`, `current.tabOf` pour la recherche), styles prêts `STYLES` = habillages `settings.ui.skin` (`UI.SKINS` de `UI/Themes.lua`, lu dans `UI.skin` : heraldic = barre latérale pleine + bandeau de titre des cartes + 1re pastille pleine, ink = cartes sans fond ni bordure + trait d'accent + boutons pleins, leather = couleurs de base cuir + titres centrés à filet + double liseré + jauges dorées ; appliqués par `UI:Card`, `UI:Progress`, `UI:Button`, `paintNav` / `GroupHead` / `RefreshChips` de `UI/MainFrame.lua` : un nouvel habillage passe par ces pièces communes, jamais par les pages), partage `STYLE_KEYS` en code « WKS1: » (`Profiles:EncodeTable` / `DecodeTable`, `UI.ApplyStyleTable`). `UI:ApplyTheme()` recopie la palette dans `UI.colors` au chargement : ne jamais réassigner `UI.colors`, et ne pas mettre de couleur en dur dans les pages (utiliser `C.*` ou `UI:Accent()`). **Un seul fond pour les fenêtres et cadres à l'écran** : `UI:HudBackground(cadre, "window"|"hud", rayon?)` (`UI/Theme.lua` : graphite `C.bg` + liseré `C.border`, 96 % pour les grandes fenêtres `UI.WINDOW_ALPHA`, opacité commune réglable `settings.ui.hudOpacity` (Options > Apparence > Fenêtre, défaut `UI.HUD_ALPHA` = 92 %, +4 % pour les grandes fenêtres) lue par `UI:HudAlpha(cadre)`, **pleine au survol** : registre `UI.hudFrames` (`UI:HudRegister(cadre, kind)` pour un cadre qui a déjà `bg` + `border`/`edge` ; `hudCustom` + `OnHudPaint` pour un fond particulier), surveillé 10 fois par seconde (`hudHover`), `UI.HudRefreshAll()` après un changement ; les cadres du mode édition à opacité baissée (`UI.hudAlphaFrames`, posé par `RegisterHUD`) passent aussi à 1 au survol ; la fenêtre principale aussi (`f.mainBg`). `UI.RefreshAccentAll()` repeint tous les crochets d'accent (entrée en jeu, ouverture de la fenêtre, si l'accent a changé : `UI.accentSig`). `UI:HudPaint` pour recolorer ; liseré à la couleur de l'apparence seulement pour ce qui doit attirer l'œil. Un nouveau cadre à l'écran passe par là. **Tout bouton est à la couleur de l'apparence (`UI:Accent()`), même au repos** : styles `UI:Button` (primary, secondary, ghost ; jamais plus étroit que son libellé, élargi quand le texte change), `UI:IconButton` (rond teinté toujours visible, liseré à partir de 20 px, `b:SetActive(on)` = fond plein pour une roue ouverte), onglets ; pas de libellé de bouton en `C.muted`. Seule exception : les boutons de suppression (`danger`).

## Disposition et taille

La fenêtre est redimensionnable en direct et les pages ne sont **jamais reconstruites** pour une nouvelle taille (WoW ne détruit pas les cadres). Une page doit donc être élastique :
- ancrer les cartes aux bords (`TOPLEFT` + `TOPRIGHT`, `BOTTOMRIGHT`…) plutôt que leur donner une largeur fixe ;
- ce qui se calcule (colonnes, tuiles, retours à la ligne) se fait dans `UI:OnResize(frame, function(w, h) ... end)` ;
- un graphique se redessine avec `UI:RefreshSoon()` depuis `OnResize`.
`UI.PAGE_W` / `UI.PAGE_H` suivent la taille en direct. La largeur minimale de contenu est de 840 px : toute page doit tenir dans cette largeur.

## Pièges connus

- Journal de combat (`COMBAT_LOG_EVENT_UNFILTERED`) : réservé au jeu, s'y inscrire ou s'en désinscrire déclenche ADDON_ACTION_FORBIDDEN. Ne jamais l'utiliser.
- `GetMerchantItemInfo` est absent : passer par `WK.MerchantItemInfo(index)`.
- `ReloadUI()` est bloqué pour les addons (ADDON_ACTION_BLOCKED « Reload() », même sur un clic) : `UI:SecureReload(bouton)` pose sur notre bouton un bouton protégé (enfant d'UIParent, macro `/reload`, retiré en combat ; appelé en combat, mis en file `pendingReload` et posé à `PLAYER_REGEN_ENABLED`) ; pour proposer de recharger après un changement : `UI:AskReload(texte)` (`UI/Widgets.lua`).

- Ne pas mélanger un ancrage haut/bas (`TOPLEFT`…) et un ancrage centré (`LEFT`, `RIGHT`) sur une même région : utiliser `TOPRIGHT` avec le même décalage vertical.
- Valeurs « secrètes » (WoW Forever cache certains GUID, noms d'effets, textes d'infobulle, effets en combat) : `issecretvalue(v)` avant tout usage (clé de table, `:match`, comparaison, calcul) ; GUID toujours par `WK.GUID(unité)` (nil si caché), jamais `UnitGUID` ; lecture des effets (`C_UnitAuras.GetAuraDataByIndex`) toujours dans un `pcall`, et pas en combat.
- Fonctions globales absentes sur ce client : passer par `WK.GetItemInfo`, `WK.InsertChatLink`, `WK.Container.*`.
- Dans une page (`UI:RegisterPage`), `self` est la définition de la page : ne pas y créer de champs `title`, `subtitle`, `nav`, `navIcon`, `count`, `key`, `order`, `frame` ou `noHeader`, utilisés par `UI/MainFrame.lua`.
- Les polices du jeu ne couvrent que le jeu de caractères Windows-1252 : pas de « → », « ≈ », « ✓ »… dans les textes affichés (utiliser « » », « · », « • »). Une estimation s'écrit « env. » (« env. 12 min ») : le « ~ » s'affiche mal avec la police du jeu.
- Noms de personnages en deux parties sur WoW Forever (« Prénom Nom », avec un espace) : le courrier exige le nom complet. Ne jamais découper un nom sur les espaces ; pour un destinataire, passer par `WK.modules.Mail:Recipient()` / `:Resolve()` / `:IsMe()`.

## Barre latérale

`UI/MainFrame.lua` : Résumé (`HOME_PAGE`) à part en haut, puis un trait ; groupes par thème (`GROUPS` : titre, entrées, icône ; Mes persos, Argent, Artisanat, Farm, Aventure, Interface) repliables par un clic sur leur titre (`GroupHead`, `settings.ui.navClosed[groupe]`, total des pastilles quand replié ; la page affichée reste visible). Une entrée « qol:<section> » est une section de la page QoL rangée avec son thème (`SubItem` : Classes et Expérience dans Mes persos, Feu de camp dans Artisanat, Carte et guidage dans Aventure, Général / Halo / Curseur / Micro menu dans Interface). Menu réduit en icônes : tout visible, sans titres. Les groupes de `Core/Features.lua` (carte Modules) sont les mêmes, chacun d'un seul tenant dans la liste.

## En-tête des pages

Plus de titre ni de phrase en haut des pages : l'en-tête affiche des pastilles de chiffres clés, définies par page dans `UI.CHIPS` (`UI/MainFrame.lua`). Chaque fonction renvoie `{ label, valeur, couleur?, page?, tip?, after? }` ; `page` rend la pastille cliquable. Une nouvelle page doit avoir ses pastilles.

## Mise à jour des données

`python3 tools/update_data.py` (lupa requis) : met à jour QuestieDB (clone dans `tools/.cache/QuestieDB`, ignoré par git, ou `--questie <clone>`), télécharge les guides (ceux de `tools/guides`) et les tables de butin de wowtbc.gg, relance tous les générateurs (lieux, chemins, rares, quêtes, donjons, guides, recettes), charge chaque fichier généré et compare les chiffres : un fichier qui ne se charge plus ou un chiffre qui chute de plus de 20 % remet tout comme avant (code 2). Résumé Markdown avec `--summary`. Options `--sans-questie`, `--sans-wowtbc`. `.github/workflows/update-data.yml` tourne chaque jour et suit `tools/update_schedule.json` (`frequence` : quotidienne / hebdomadaire (lundi) / manuelle ; `publier`), modifiable depuis le client PC (Réglages > Données). `publier: false` : PR `data-update/<date>` (l'ancienne PR ouverte est fermée), à intégrer puis publier comme une version. `publier: true` : `tools/publish_data.py` monte la version d'un cran, écrit l'entrée « Données mises à jour… » du changelog à partir des chiffres (`--json` de update_data.py), pousse sur main et lance `release.yml`. Un nouveau générateur doit y être ajouté (étape et chiffres dans `metrics()`).

## Publication et client PC

Chaque push sur main qui change `## Version` lance `.github/workflows/release.yml` : Release `vX.Y.Z` avec `WarbandKeeper-X.Y.Z.zip` (`tools/build_zip.py` : dossiers WarbandKeeper et WarbandKeeper_Data ; `.gitattributes` exclut `.github`, `client`, `tools`, `CLAUDE.md`) et les notes de la version tirées de `CHANGELOG.md`, puis l'exe du client construit sur Windows (PyInstaller) et joint à la Release. `client/wk_client.py` (Tkinter, thème Graphite avec accent bleu électrique, pas de rose ; pages déclarées par `@page`) : détection de WoW (`find_installs` : registre, Battle.net.config, disques ; WoW Forever reconnu par le dossier, `.flavor.info` ou des addons en interface 16xxx ; **seules les installations WoW Forever sont proposées** (`find_forever`), un autre dossier demande confirmation ; choix si plusieurs), redémarrage ou /reload calculé à l'installation (`install_zip` : nouveaux fichiers ou .toc modifié), lit les Releases (jeton fine-grained en lecture seule tant que le dépôt est privé), installe le zip dans Interface\AddOns (sauvegarde des SavedVariables avant, version précédente gardée dans `%APPDATA%\WarbandKeeper Client`), se met à jour lui-même (asset `WarbandKeeper-Client-<CLIENT_VERSION>.exe` ; `best_client` cherche le plus récent dans toutes les Releases, et la Release d'une nouvelle version de l'addon reçoit tout de suite l'exe et les notes de la précédente, remplacés quand le job Windows a fini). Monter `CLIENT_VERSION` à chaque changement du client et noter le changement dans **`client/CHANGELOG.md`** (notes du client, à part : jamais dans `Core/Changelog.lua`, qui ne parle que de l'addon) ; la Release ajoute « ## Client PC x.y.z » à ses notes et joint `WarbandKeeper-Client-notes.md`. Réglages du client : Mises à jour (`checkEvery`, toutes les heures par défaut ; nouvelle version signalée par `flash_taskbar`, le titre et un message ; `autoInstall` ; `startup` = clé Run de Windows, lancé avec `--minimized`), Données (planning GitHub, jeton en écriture). Logo : `client/make_assets.py`. Mode d'emploi : `client/README.md`.

Mis à jour par `update_data.py` (chiffres « Objets avec taux de drop observé », « Trajets de vol »). ## Guides de montée des métiers

`Modules/Guides.lua` est **généré** par `python3 tools/gen_guides.py` depuis `tools/guides/*.json` (extraits des guides WoW Forever de wowtbc.gg). Pour ajouter ou mettre à jour un métier : télécharger `https://wowtbc.gg/page-data/warcraftforever/professions/<métier>/page-data.json` puis `python3 tools/gen_guides.py --import <fichier>`. Une remarque de maître nouvelle doit être traduite dans `NOTES` du générateur (et en anglais dans `Locales/enUS.lua`).
- Raccourcis clavier : nom posé par `WK.BindingName(global, texte français)` (`Locales/Locale.lua`, reposé dans la langue choisie à la connexion et au changement de langue par `WK.RefreshBindingNames`), jamais `_G["BINDING_NAME_…"] = T(…)` au chargement.
- Infobulles : toujours `WK.UI:TooltipOwner(owner, anchor)` au lieu de `GameTooltip:SetOwner` ; elle habille l'infobulle aux couleurs de l'addon (le cadre du jeu revient à la fermeture). Les infobulles du jeu (`GAME_TOOLTIPS` de `UI/Widgets.lua` : GameTooltip, ItemRefTooltip, comparaisons…) sont aussi habillées à chaque affichage quand `settings.ui.gameTooltipFont` est actif (un habillage par infobulle, `skins[tt]`).

## Rangement des réglages (un seul endroit par réglage)

Chaque réglage a une seule place, à côté de sa fonction : roue dentée en haut à droite de la page (`UI:PageGear(p, { cards, top, columns, icon, onToggle }, def)` dans `UI/Widgets.lua` : volet posé sur le contenu, cartes reprises dès la construction, `RevealSetting` pour la recherche). Les cartes restent construites dans leur section d'origine de QoL ou d'Options (helpers `card()` qui notent `current.cards` et `c.cardKey`) et sont reprises par `UI:SectionCards(page, section, titres)` ; `UI:EnsurePage(clé)` construit une page sans l'afficher. Où est quoi :
- Inventaire (roue) : règles des objets verrouillés, protection, perso HV ; Courrier (page `mail`, roue) : sections `mail` d'Options ; Hôtel des ventes : onglet de QoL > Général = section `ah` de QoL, avec la carte « Prix des objets » (section `prices` d'Options) en tête (plus de page `auction` : `UI:ShowPage("auction")` ouvre cet onglet) ;
- Métiers (roue) : aides, fenêtres du jeu, file, récolte + section `glow` d'Options ; Pêche (roue) : section `fishing` de QoL ;
- Quêtes, Rares, Donjons : roue (Donjons : `Dungeons:Config()` panel, alertEnter, alertDrop, timer) ; Persos : bouton Expérience (cartes `xpData` de QoL > Expérience) ;
- QoL > Général > Carte et guidage (plus dans la barre latérale ; la section `maplayers` est posée sous la barre de Général, ses onglets en 2e niveau soulignés `UI:UnderTabs` via `sec.underTabs` ; onglets de Général qui portent une section : `gsec.embeds` + `gsec.syncEmbed`, `ShowSection("ah"|"maplayers")` redirige ; onglet Guidage : carte de `Guide:Config()` et navigation) ; QoL > Général > Alertes (état des persos + cartes de la section `alerts` d'Options, rangées en sous-onglets `UI:CardTabs` « qolAlerts » : État des persos, Alertes, Connexion, À faire ; `sec.innerReveal` pour la recherche ; `UI:OpenQoLAlerts()`) ;
- Options : Général (langue, Infobulles = cartes « Objets » et « PNJ et apparence », bouton minimap, combat), Apparence, À propos ; « Rappels à la connexion » est dans la section cachée `alerts` (affichée dans QoL > Général > Alertes) ; les sections `prices`, `mail`, `glow`, `alerts` sont cachées (cartes reprises).
Un nouveau réglage va dans la roue de sa page ; une nouvelle ligne d'infobulle dans Options > Infobulles. Toute roue range ses cartes en **sous-onglets de catégories** : `UI:CardTabs(parent, id, tabs, onChange)` (`UI/Widgets.lua` : `tabs` = { { clé, libellé, titles = { titres de cartes } } }, ou `carte.gearTab` ; `ct:Filter(cartes)`, `ct.bar`, `ct:Height()`, `ct:Reveal(carte)` pour la recherche, onglet retenu dans `settings.ui.gearTabs[id]`, `carte.keepHidden()` pour une carte repliée) ; `UI:PageGear` le fait seul avec `opts.tabs` / `opts.id`. Une nouvelle carte de réglages doit être citée dans les `titles` de son onglet (sinon elle tombe dans le dernier).

## Qualité de vie (QoL)

`Modules/QoL.lua` porte les données (composants par classe dans `M.REAGENTS`, coffres, villes de portail), les réglages (`WK.DB.global.qol`, complétés par `QoL:Config()`), les alertes (`QoL:Alerts()`, reprises par « À faire » et les pastilles) et les automatisations. `UI/Pages/QoL.lua` est la page (sections Général… Classes, choisies dans la barre latérale sous « QoL » : `UI.QOL_SECTIONS`, `UI:QoLSectionCount`, `UI:QoLCurrentSection` ; la colonne interne est masquée). Onglets dans une section : `subtab(nom, ordre)` avant les cartes (un nom déjà vu reprend son onglet, ce qui précède le premier reste au-dessus), barre posée par `closeSection` (onglets vides retirés, un seul onglet = pas de barre), onglet retenu dans `settings.ui.qolTabs[section]`, `sec.showTab(i)` / `sec.tabOf(cadre)` (utilisé par la recherche). Carte, Général et chaque classe sont en onglets. Les actions que le jeu protège (supprimer un objet, nourrir le familier, changer d'armes) passent par un clic du joueur ou une macro, jamais en combat. Rappels à l'écran **retirés** à la demande du joueur (pile, pastilles, messages éclair, texte rouge, `UI/AlertStack.lua` supprimé) : `QoL:Remind` / `ClearRemind` restent sans effet pour les modules qui les appellent, `UI.SetAlert` n'existe plus (les appels sont gardés par `if UI.SetAlert`) ; ce qui compte passe par le chat du module. Ne pas remettre de pile de rappels. `Modules/Fishing.lua` gère le « mode pêche » (tenue, appâts, sons, touche unique, butin rapide, avertissements) ; `UI/FishingBar.lua` la barre à l'écran et le bouton de minicarte ; les réglages sont dans `QoL:Config().fishing` ; leurs cartes sont construites dans la section « fishing » de `UI/Pages/QoL.lua` (`self.fishSection`, absente de la barre latérale ; cartes du carnet marquées `journal`) puis reprises par la page Pêche (`UI/Pages/FishCollection.lua` : onglets Collection et Carnet, roue dentée des réglages sur deux colonnes, `Adopt`, `RevealSetting` pour la recherche, `UI:OpenFishSettings()` ; `UI:EnsurePage(clé)` construit une page sans l'afficher). Le lancer et la pose d'appât passent par le bouton protégé `WarbandKeeperFishButton` (macro préparée juste avant le clic, hors combat). La touche unique est une liaison temporaire (`SetOverrideBinding`), posée seulement en mode pêche : elle clique le bouton, ou ferre avec `INTERACTTARGET` quand le flotteur est désigné. Tout ce que le mode change (équipement, sons, réglages de désignation) est sauvegardé et rendu à la fermeture.

Carnet de pêche : `Modules/FishingLog.lua` note chaque butin de pêche (`Record`, appelé par le butin rapide de `Modules/Fishing.lua` avant de ramasser) dans `WK.DB.global.fishLog` (hors profils), et tient la session du mode pêche ; `UI/FishingRecap.lua` affiche le récapitulatif à la fermeture ; le carnet est dans l'onglet Carnet de la page Pêche. Collection : `Modules/FishDB.lua` (référence écrite à la main, numéros d'objets vérifiés : espèces par catégorie et palier, zones avec compétence conseillée), `FishingLog:Collection()`, `:Atlas()`, `:SpeciesZones()`, `:GuideZone()` (dernier coin de pêche noté par zone, `zones[carte].pos`) ; `UI/FishingCollection.lua` dessine la carte (onglets Album et Par zone, hauteur variable), affichée dans la page « Pêche » du groupe Farm (`UI/Pages/FishCollection.lua`, clé `fishing`, module « fishing »).

`UI/CorpseBanner.lua` : fantôme, épingle à l'écran en tête de mort rouge (`UI/NavPin.lua`, genre « corpse » : conseil, distance du trajet + temps, coût de l'ange via `UI:CorpsePinInfo(d)`) ; HUD `corpseBanner` seulement quand l'épingle ne guide pas (autre continent, position inconnue, `screenPin` coupé) (distance, temps à pied, coût de l'ange gardien, conseil au-delà de 3 min), guidage vers le corps (`Guide:Start`, genre « corpse », guidage d'avant rendu une fois en vie) ; corps : `C_DeathInfo.GetCorpseMapPosition`, sinon l'endroit de la mort ; réglage `Guide:Config().corpse`.

`Modules/MapRevealDB.lua` est **généré** par `python3 tools/gen_reveal.py` (tables WorldMapOverlay, WorldMapOverlayTile, UiMapXMapArt, UiMapArt, UiMapArtStyleLayer du jeu, wago.tools ; dans `update_data.py`, chiffre « Cartes sans brouillard »). `UI/MapReveal.lua` : calque « Brouillard » de `UI/MapPins.lua`, zones non découvertes (absentes de `C_MapExplorationInfo.GetExploredMapTextures`) dessinées au niveau du calque d'exploration du jeu ; réglages `MapLayers:Config().reveal` / `revealTint` (QoL > Carte, Filtres et affichage).

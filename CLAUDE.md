# Warband Keeper : consignes de développement

Addon World of Warcraft (client WoW Forever, `## Interface: 16001`, API moderne : `C_Item`, `C_Container`, `TooltipDataProcessor`…). Toute l'interface et les textes sont en français.

## Notes de patch (obligatoire à chaque modification)

Chaque ajout, modification ou correction doit être noté **dans le même commit** :

1. Dans `Core/Changelog.lua` :
   - nouvelle version : ajouter une entrée **en tête** de `WK.Changelog` (version, date `JJ/MM/AAAA`, listes `added`, `changed`, `fixed`) ;
   - changement non publié : compléter l'entrée de tête.
   - `restart = true` dans l'entrée quand il faut redémarrer complètement le jeu (nouveau `.lua`, nouvelle texture, `.toc` modifié) ; sinon rien (un /reload suffit). Affiché en jeu (pastille), dans `CHANGELOG.md` et dans les Releases (le workflow corrige la mention s'il voit de nouveaux fichiers) ; le client le recalcule à l'installation.
   - Phrases courtes, en français, du point de vue du joueur (ce qui change pour lui, pas le détail du code). Une correction dit ce qui n'allait pas.
2. Déplacer de `WK.Roadmap` ce qui vient d'être livré ; y ajouter les idées acceptées mais pas encore commencées.
3. Monter la version dans `WarbandKeeper.toc` (`## Version`) **et** `Core/Init.lua` (`WK.version`) ; elles doivent être identiques à la version de tête du changelog.
4. Régénérer `CHANGELOG.md` : `python3 tools/gen_changelog.py`.

## Textures

Les textures de `Media/` sont générées par `python3 tools/gen_media.py` (Pillow). Un nouveau fichier de texture ou un nouveau `.lua` demande de **redémarrer le jeu** (un `/reload` ne suffit pas) : le signaler dans la note de version.

## Thèmes

Les couleurs viennent de `UI/Themes.lua` (un seul thème proposé : Graphite, imposé par `UI:ApplyTheme` ; les autres restent dans `UI.themes` sans choix dans les Options) : un thème donne quelques couleurs de base (`bg`, `line`, `frame`, `glow`, `text`, `muted`, `accent`) et `palette()` dérive le reste. Couleurs de sens communes à tous les thèmes : `positive`, `negative`, `warning`, `gold`, `tank`, `heal`, `dps`, `rare`, `info` (bleu : repos), `rule` (turquoise : automatique, par règle), `plan` (violet : mode plan), `silver` (secondaire, autre perso), `mint` (pastille de compte) ; dans un texte, `UI:Hex(C.x)`. `UI:ApplyTheme()` recopie la palette dans `UI.colors` au chargement : ne jamais réassigner `UI.colors`, et ne pas mettre de couleur en dur dans les pages (utiliser `C.*` ou `UI:Accent()`). **Tout bouton est à la couleur de l'apparence (`UI:Accent()`), même au repos** : styles `UI:Button` (primary, secondary, ghost), `UI:IconButton` (rond teinté toujours visible, liseré à partir de 20 px, `b:SetActive(on)` = fond plein pour une roue ouverte), onglets ; pas de libellé de bouton en `C.muted`. Seule exception : les boutons de suppression (`danger`).

## Disposition et taille

La fenêtre est redimensionnable en direct et les pages ne sont **jamais reconstruites** pour une nouvelle taille (WoW ne détruit pas les cadres). Une page doit donc être élastique :
- ancrer les cartes aux bords (`TOPLEFT` + `TOPRIGHT`, `BOTTOMRIGHT`…) plutôt que leur donner une largeur fixe ;
- ce qui se calcule (colonnes, tuiles, retours à la ligne) se fait dans `UI:OnResize(frame, function(w, h) ... end)` ;
- un graphique se redessine avec `UI:RefreshSoon()` depuis `OnResize`.
`UI.PAGE_W` / `UI.PAGE_H` suivent la taille en direct. La largeur minimale de contenu est de 840 px : toute page doit tenir dans cette largeur.

## Pièges connus

- Journal de combat (`COMBAT_LOG_EVENT_UNFILTERED`) : réservé au jeu, s'y inscrire ou s'en désinscrire déclenche ADDON_ACTION_FORBIDDEN. Ne jamais l'utiliser.
- `GetMerchantItemInfo` est absent : passer par `WK.MerchantItemInfo(index)`.

- Ne pas mélanger un ancrage haut/bas (`TOPLEFT`…) et un ancrage centré (`LEFT`, `RIGHT`) sur une même région : utiliser `TOPRIGHT` avec le même décalage vertical.
- Fonctions globales absentes sur ce client : passer par `WK.GetItemInfo`, `WK.InsertChatLink`, `WK.Container.*`.
- Dans une page (`UI:RegisterPage`), `self` est la définition de la page : ne pas y créer de champs `title`, `subtitle`, `nav`, `navIcon`, `count`, `key`, `order`, `frame` ou `noHeader`, utilisés par `UI/MainFrame.lua`.
- Les polices du jeu ne couvrent que le jeu de caractères Windows-1252 : pas de « → », « ≈ », « ✓ »… dans les textes affichés (utiliser « » », « ~ », « · », « • »).
- Noms de personnages en deux parties sur WoW Forever (« Prénom Nom », avec un espace) : le courrier exige le nom complet. Ne jamais découper un nom sur les espaces ; pour un destinataire, passer par `WK.modules.Mail:Recipient()` / `:Resolve()` / `:IsMe()`.

## Barre latérale

`UI/MainFrame.lua` : Résumé (`HOME_PAGE`) à part en haut, puis un trait ; groupes par thème (`GROUPS` : titre, entrées, icône ; Mes persos, Argent, Artisanat, Farm, Aventure, Interface) repliables par un clic sur leur titre (`GroupHead`, `settings.ui.navClosed[groupe]`, total des pastilles quand replié ; la page affichée reste visible). Une entrée « qol:<section> » est une section de la page QoL rangée avec son thème (`SubItem` : Classes et Expérience dans Mes persos, Feu de camp dans Artisanat, Carte et guidage dans Aventure, Général / Halo / Curseur / Micro menu dans Interface). Menu réduit en icônes : tout visible, sans titres. Les groupes de `Core/Features.lua` (carte Modules) sont les mêmes, chacun d'un seul tenant dans la liste.

## En-tête des pages

Plus de titre ni de phrase en haut des pages : l'en-tête affiche des pastilles de chiffres clés, définies par page dans `UI.CHIPS` (`UI/MainFrame.lua`). Chaque fonction renvoie `{ label, valeur, couleur?, page?, tip?, after? }` ; `page` rend la pastille cliquable. Une nouvelle page doit avoir ses pastilles.

## Mise à jour des données

`python3 tools/update_data.py` (lupa requis) : met à jour QuestieDB (clone dans `tools/.cache/QuestieDB`, ignoré par git, ou `--questie <clone>`), télécharge les guides (ceux de `tools/guides`) et les tables de butin de wowtbc.gg, relance tous les générateurs (lieux, chemins, rares, quêtes, donjons, guides, recettes), charge chaque fichier généré et compare les chiffres : un fichier qui ne se charge plus ou un chiffre qui chute de plus de 20 % remet tout comme avant (code 2). Résumé Markdown avec `--summary`. Options `--sans-questie`, `--sans-wowtbc`. `.github/workflows/update-data.yml` tourne chaque jour et suit `tools/update_schedule.json` (`frequence` : quotidienne / hebdomadaire (lundi) / manuelle ; `publier`), modifiable depuis le client PC (Réglages > Données). `publier: false` : PR `data-update/<date>` (l'ancienne PR ouverte est fermée), à intégrer puis publier comme une version. `publier: true` : `tools/publish_data.py` monte la version d'un cran, écrit l'entrée « Données mises à jour… » du changelog à partir des chiffres (`--json` de update_data.py), pousse sur main et lance `release.yml`. Un nouveau générateur doit y être ajouté (étape et chiffres dans `metrics()`).

## Publication et client PC

Chaque push sur main qui change `## Version` lance `.github/workflows/release.yml` : Release `vX.Y.Z` avec `WarbandKeeper-X.Y.Z.zip` (git archive ; `.gitattributes` exclut `.github`, `client`) et les notes de la version tirées de `CHANGELOG.md`, puis l'exe du client construit sur Windows (PyInstaller) et joint à la Release. `client/wk_client.py` (Tkinter, thème Graphite avec accent bleu électrique, pas de rose ; pages déclarées par `@page`) : détection de WoW (`find_installs` : registre, Battle.net.config, disques ; WoW Forever reconnu par le dossier, `.flavor.info` ou des addons en interface 16xxx ; **seules les installations WoW Forever sont proposées** (`find_forever`), un autre dossier demande confirmation ; choix si plusieurs), redémarrage ou /reload calculé à l'installation (`install_zip` : nouveaux fichiers ou .toc modifié), lit les Releases (jeton fine-grained en lecture seule tant que le dépôt est privé), installe le zip dans Interface\AddOns (sauvegarde des SavedVariables avant, version précédente gardée dans `%APPDATA%\WarbandKeeper Client`), se met à jour lui-même (asset `WarbandKeeper-Client-<CLIENT_VERSION>.exe` ; `best_client` cherche le plus récent dans toutes les Releases, et la Release d'une nouvelle version de l'addon reçoit tout de suite l'exe et les notes de la précédente, remplacés quand le job Windows a fini). Monter `CLIENT_VERSION` à chaque changement du client et noter le changement dans **`client/CHANGELOG.md`** (notes du client, à part : jamais dans `Core/Changelog.lua`, qui ne parle que de l'addon) ; la Release ajoute « ## Client PC x.y.z » à ses notes et joint `WarbandKeeper-Client-notes.md`. Réglages du client : Mises à jour (`checkEvery`, toutes les heures par défaut ; nouvelle version signalée par `flash_taskbar`, le titre et un message ; `autoInstall` ; `startup` = clé Run de Windows, lancé avec `--minimized`), Données (planning GitHub, jeton en écriture). Logo : `client/make_assets.py`. Mode d'emploi : `client/README.md`.

## Guides de montée des métiers

`Modules/Guides.lua` est **généré** par `python3 tools/gen_guides.py` depuis `tools/guides/*.json` (extraits des guides WoW Forever de wowtbc.gg). Pour ajouter ou mettre à jour un métier : télécharger `https://wowtbc.gg/page-data/warcraftforever/professions/<métier>/page-data.json` puis `python3 tools/gen_guides.py --import <fichier>`. - Infobulles : toujours `WK.UI:TooltipOwner(owner, anchor)` au lieu de `GameTooltip:SetOwner` ; elle habille l'infobulle aux couleurs de l'addon (le cadre du jeu revient à la fermeture). Les infobulles du jeu (`GAME_TOOLTIPS` de `UI/Widgets.lua` : GameTooltip, ItemRefTooltip, comparaisons…) sont aussi habillées à chaque affichage quand `settings.ui.gameTooltipFont` est actif (un habillage par infobulle, `skins[tt]`).

## Rangement des réglages (un seul endroit par réglage)

Chaque réglage a une seule place, à côté de sa fonction : roue dentée en haut à droite de la page (`UI:PageGear(p, { cards, top, columns, icon, onToggle }, def)` dans `UI/Widgets.lua` : volet posé sur le contenu, cartes reprises dès la construction, `RevealSetting` pour la recherche). Les cartes restent construites dans leur section d'origine de QoL ou d'Options (helpers `card()` qui notent `current.cards` et `c.cardKey`) et sont reprises par `UI:SectionCards(page, section, titres)` ; `UI:EnsurePage(clé)` construit une page sans l'afficher. Où est quoi :
- Inventaire (roue) : règles des objets verrouillés, protection, perso HV ; Courrier (page `mail`, roue) : sections `mail` d'Options ; Hôtel des ventes (page `auction`, `UI/Pages/AuctionHouse.lua`) : section `prices` d'Options + section `ah` de QoL ;
- Métiers (roue) : aides, fenêtres du jeu, file, récolte + section `glow` d'Options ; Pêche (roue) : section `fishing` de QoL ;
- Quêtes, Rares, Donjons : roue (Donjons : `Dungeons:Config()` panel, alertEnter, alertDrop, timer) ; Persos : bouton Expérience (cartes `xpData` de QoL > Expérience) ;
- QoL > Carte et guidage (onglet Guidage : carte de `Guide:Config()` et navigation) ; QoL > Général > Alertes (état des persos + sections `alerts` et « Rappels à la connexion » d'Options, `UI:OpenQoLAlerts()`) ;
- Options : Général (langue, Infobulles = toutes les lignes d'infobulle, bouton minimap, combat), Apparence, À propos ; les sections `prices`, `mail`, `glow`, `alerts` sont cachées (cartes reprises).
Un nouveau réglage va dans la roue de sa page ; une nouvelle ligne d'infobulle dans Options > Infobulles.

## Qualité de vie (QoL)

`Modules/QoL.lua` porte les données (composants par classe dans `M.REAGENTS`, coffres, villes de portail), les réglages (`WK.DB.global.qol`, complétés par `QoL:Config()`), les alertes (`QoL:Alerts()`, reprises par « À faire » et les pastilles) et les automatisations. `UI/Pages/QoL.lua` est la page (sections Général… Classes, choisies dans la barre latérale sous « QoL » : `UI.QOL_SECTIONS`, `UI:QoLSectionCount`, `UI:QoLCurrentSection` ; la colonne interne est masquée). Onglets dans une section : `subtab(nom, ordre)` avant les cartes (un nom déjà vu reprend son onglet, ce qui précède le premier reste au-dessus), barre posée par `closeSection` (onglets vides retirés, un seul onglet = pas de barre), onglet retenu dans `settings.ui.qolTabs[section]`, `sec.showTab(i)` / `sec.tabOf(cadre)` (utilisé par la recherche). Carte, Général et chaque classe sont en onglets. Les actions que le jeu protège (supprimer un objet, nourrir le familier, changer d'armes) passent par un clic du joueur ou une macro, jamais en combat. Rappels : `QoL:Remind(clé, texte, r, g, b, quiet, opts)` (opts : `action`, `right`, `ttl`, `urgent`, `noText`) et `ClearRemind` ; genre de rappel par clé (`REMIND_KINDS`, `RemindKind`), destination choisie dans `RemindCfg()` (pile / texte rouge / les deux / rien, son), carte « Où vont les rappels » de Général > Alertes. Bouton « Buffer le suivant » (`UI/BuffButton.lua`, `WK.BUFF_CLASSES`) : candidats = toi, groupe, plaques de nom amies (`C_NamePlate`), buff par classe (paladin selon la classe du joueur, `kingsFirst`), bouton protégé `WarbandKeeperBuffButton` (sort et unité posés hors combat, caché à `PLAYER_REGEN_DISABLED`), liseré sur la plaque, réglages `buffAround`, `buffRefresh`, `buffInstance`, `buffMounted`, `buffPlates` (CVar `nameplateShowFriends`, ancienne valeur dans `buffPlatesOld`), onglet « Buffer autour » des classes. Pile d'alertes (`UI/AlertStack.lua`) : cadre « Rappels » repliable (`collapsed`, `combatFold` dans l'entrée HUD), groupes `urgent` / `perso` / `world`, `UI:SetAlert(clé, shown, { text, color, prio, group, right, ttl, dismiss, action = { label, onClick | attrs } })` ; boutons d'attributs protégés (enfants d'UIParent, posés hors combat, détachés à `PLAYER_REGEN_DISABLED`).

## Bénédictions du paladin

## Navigation

`Modules/RoadsDB.lua` est **généré** par `python3 tools/gen_roads.py <clone de QuestieDB>` : trajets de patrouille des PNJ (chemins praticables), simplifiés (données Questie, GPLv3 : garder la mention). `Modules/Nav.lua` : graphe des chemins par continent (coordonnées monde de `Guide.ToWorld` : x nord, y ouest, en mètres du jeu), chemins de base + chemins appris (`WK.DB.global.nav.trails`, hors profils : tronçons nouveaux seulement, simplifiés), A* étalé sur plusieurs images (hors chemins : coût `OFF` fois la distance), vols connus du perso (`characters[perso].taxi`, notés à `TAXIMAP_OPENED`), quai vers un autre continent (`MapLayers.TRANSPORTS`), suivi (`Nav:Waypoint()` pour la flèche, recalcul quand on s'écarte). `Guide:Start` lance `Nav:Plan`, `Guide:Stop` `Nav:Clear`. `UI/NavRoute.lua` dessine les pointillés (carte du monde via `UI/MapPins.lua`, minicarte). ## Fiabilité

Performances : `/wk perf [s]` (`Maintenance:PerfStart` / `PerfStop`) chronomètre les évènements (`WK.perf` dans le répartiteur de `Core/Init.lua`), les fonctions de `HOT` et les OnUpdate des cadres nommés `WarbandKeeper*`. Évènements très fréquents d'une seule unité : `WK:OnUnit(évènement, unités, fn)` (RegisterUnitEvent) plutôt que `WK:On` ; UNIT_HEALTH des donjons sur un cadre à part, écouté seulement en instance (`Dungeons.WatchHealth`). Quêtes : lignes de `QuestsDB` indexées sans copie (métatable `QMETA`).

`Modules/Maintenance.lua` (chargé juste après Core) : journal d'erreurs `WK.DB.global.errors` (`list` = { m, s, n, first, last, v, new }, 50 au plus, hors profils), alimenté par le gestionnaire d'erreurs du jeu (enrobé, l'ancien toujours appelé ; seulement nos fichiers), les erreurs des évènements de `WK:On` (`WK.RecordError`) et `ADDON_ACTION_BLOCKED` / `FORBIDDEN` ; `Unseen`, `MarkSeen`, `Report`, `Clear`. Nettoyage : `SizeOf` / `Total` (taille estimée), `PURGES` (clé, titre, cochée d'office, `scan` = nombre, octets, détail ; `run`), `Scan`, `Clean`. `UI/Maintenance.lua` : section « Fiabilité » des Options (`UI:BuildMaintenanceCards`, `UI:RefreshMaintenance`, fenêtre du rapport `UI:ShowErrorReport`) ; point rouge de l'icône Options (`count` = « ! »). Une nouvelle donnée qui grossit sans fin doit avoir sa purge dans `PURGES`.

## Recherche et profils

`UI/Search.lua` : la recherche de la barre latérale. Chaque `UI:SettingRow` s'inscrit dans `UI.settingIndex` ; à la première recherche, les pages pas encore ouvertes sont construites (cachées) pour être indexées. Un nouveau réglage est donc trouvable s'il passe par `UI:SettingRow`. L'index est retenu dans `WK.DB.global.searchIndex` (version de l'addon et langue) : les pages ne sont toutes construites qu'une fois par version, ensuite seule la page d'un résultat l'est (`findRow`). `Modules/Profiles.lua` : profils de réglages (section « Profils » des Options, cartes de `UI/Pages/Profiles.lua`), appliqués par `Core/Init.lua` juste après `WK.DB:Init()` (avant tout le reste). La liste `KEYS` dit ce qu'un profil contient (clés de `WK.DB.global`, sous-clés de données exclues) : un nouveau réglage rangé ailleurs doit y être ajouté, une nouvelle donnée de compte rangée dans ces clés doit y être exclue.
